# docs/planning

Specs and plans for QuickMail features, written before the code (see `SPEC-TEMPLATE.md` and
`USING-THE-TEMPLATE.md`).

- **This folder** holds work that is proposed, in progress, or partly shipped.
- **`Completed/`** holds specs and plans whose work has shipped or been superseded. They are kept
  as the record of why things were built the way they were, so their status lines and "next steps"
  describe the time they were written, not today. The code, `docs/ARCHITECTURE.md` and the user
  guide describe what QuickMail does now.

Move a spec into `Completed/` in the change that finishes its work, and fix any links to it.

Writing about the project (blog drafts, retrospectives, old branch reviews) lives in
`docs/history/`.
