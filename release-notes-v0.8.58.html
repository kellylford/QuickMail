QuickMail v0.8.58 Release Notes

Released October 16, 2026 — downloads for this release

Fixed

A message you send is in the Sent folder once, not twice

Many mail services, Gmail, iCloud and Outlook.com among them, file their own copy of every message they send for you, and QuickMail then added a second one. QuickMail now checks the Sent folder for the service’s copy and adds its own only when there isn’t one. Messages sent before this release keep their duplicate copies; delete either one (#811, #150).

Rules, Find mail from this contact, and search now can find a sender by address on every account type

On Gmail, other IMAP accounts and POP3 accounts, QuickMail kept only the sender’s name for the message list, so anything that looked for the sender’s email address had nothing to find. A client-side rule with a From addresses condition never matched mail from a sender who has a display name, Find mail from this contact in the address book came up empty for those senders, and a search such as from:@example.com missed them. Microsoft 365 and Outlook.com accounts did support this as expected. QuickMail now properly supports it for all account types by keeping each sender’s address alongside the name on every account type. From now on, rules, Find mail from this contact, and both kinds of search can find a sender by their address as well as their name (#803).

Create Rule from Message now fills in the sender’s email address instead of their name, so a rule made from a message from “PayPal” no longer also catches someone else calling themselves “PayPal”. Where QuickMail doesn’t have the address yet, it fills in the name, as before. When a client-side rule’s Sender contains or From addresses holds an email address, or part of one such as @example.com, it is checked against the sender’s actual address, so a sender can’t match it by putting that address in their display name. Find mail from this contact works the same way. Text without an @, such as a name, still matches the display name. Until the one-time update described below has reached a message, QuickMail has only the name to check, as before.

The first time you start this version, QuickMail fills in the address for mail it already has. Most of it comes from what is already on this computer. For IMAP mail whose text has not been downloaded, it asks the server for the sender alone, a batch at a time, and shows its progress in its own part of the status bar, which goes away when it’s done. To check on it, press Ctrl+9 to reach the status bar and Right to move along it. Nothing is moved, deleted or marked, and your rules do not run again.

Contributed by valiant8086.

A Microsoft account’s message list says the sender’s name

On a Microsoft 365 or Outlook.com account, each row in the message list showed and spoke the sender’s address after the name like News <news@example.com>, where every other kind of account says the name alone. Microsoft accounts now work like the rest, saying the name, or the address when the sender has none (#801).

Contributed by valiant8086.

Message properties now always show both the sender’s name and address

Properties (Alt+Enter) on an individual message now shows both the display name (when available) and the email address, on every account, even for a message whose text has not been downloaded. Previously, it tended to only show the display name (#801).

The same goes for a conversation, and for a sender’s group in the From view: their Properties now list each sender as name and address. A sender’s group is gathered by name, so if mail under that name came from more than one address, each address is listed, and someone else using a familiar name shows up there.

Contributed by valiant8086.

Thank You

Thank you to valiant8086, who noticed that Microsoft accounts were the only ones putting the sender’s address in the message list, traced that to every other account type keeping no address at all, and wrote the fix for both. Their careful manual testing also caught problems that a code review alone would have missed.
