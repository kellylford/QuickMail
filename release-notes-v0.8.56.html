QuickMail v0.8.56 Release Notes

Released October 13, 2026 — downloads for this release

New: folders of your own on a POP3 account

A POP3 account used to have only Inbox, Sent, Drafts and Trash, so there was nowhere to file a mailing list or anything else (#794). Now you can create folders on a POP3 account the same way as on any other: Folder → New Folder…, the folder tree’s context menu, or New Folder in the folder picker, including while choosing a rule’s folder. Move and copy messages into them, point rules at them, and move, copy or delete them like any other folder.

A POP3 server has no folders, so these folders and the mail in them exist only on this computer. Deleting one moves its mail, and the mail of any folders inside it, to Trash. Inbox, Sent, Drafts and Trash stay as they are and cannot be moved or deleted. Exporting your settings does not carry these folders or their mail to another computer.

Fixed

A rule whose move or delete failed could lose the message

When a rule could not move or delete a message (because the folder it files into had been deleted, say, or the connection dropped), QuickMail still treated the message as gone and took it out of its folder on this computer. On an IMAP or Microsoft 365 account the message was still on the server and came back later. On a POP3 account this computer holds the only copy, so the message was lost. Now a message stays where it is when its rule’s move or delete fails (#794).

Opening a message starts reading it again

Since 0.8.55, opening a message with a screen reader running often stopped on the message’s subject instead of reading the message, and you had to press Tab before reading began. It happened in the reading pane, in a message opened in its own window, and in the Markdown preview. Opening a message now goes straight into reading it, as it did before. Ctrl+A, Ctrl+C still copies the whole message, which was the fix in 0.8.55 that caused this.
